# Internationalisation (English / Ελληνικά)

The web app uses **react-i18next**. Languages: `en` (default/fallback) and `el` (Greek).

## Structure
```
app/src/i18n/
  index.ts                    # init, language detection (localStorage → browser), helpers
  locales/en/<namespace>.json
  locales/el/<namespace>.json # same keys as en
```
Namespaces are discovered automatically — add `locales/en/foo.json` **and** `locales/el/foo.json`.
`common` is the default namespace (shared actions, states, units, counts, domain terms).

## Usage
```tsx
const { t } = useTranslation("quizzes");          // default ns for this component
t("title");                                         // quizzes:title
t("common:actions.save");                           // other namespace
t("count", { count: 3 });                           // plurals: key_one / key_other
<Trans i18nKey="quizzes:intro" components={{ b: <strong /> }} />   // rich text
```
Outside React (services, hooks, toasts, option arrays): `tr("ns:key")` from `@/lib/i18n-options`, or `i18n.t`.
Dropdown/label vocabulary: `tOption(id, "ns:key")` — the `label` is a getter, so module-level arrays follow the active language.
Dates/numbers: `formatDate`, `formatRelative`, `formatDuration` (`@/lib/date`) and `formatNumber`, `formatPercent`, `tCount` (`@/lib/format`) are locale-aware.

## Rules
- No hard-coded user-visible strings in TSX, toasts, `aria-label`, `placeholder`, `title`, `alt`, error messages or option labels.
- Keep keys semantic and grouped (`page.title`, `form.fields.title.label`, `toasts.created.title`, `empty.title`).
- Interpolate values (`{{name}}`, `{{count}}`) — never concatenate translated fragments.
- Run `npm run i18n:check` (parity + unknown keys) and `npm run i18n:scan` (possible hard-coded strings).
- Server/AI-generated content (summaries, questions, flashcards, topics, tutor answers) is in the **project's language**; server notifications & emails are localised from the user's `language` preference.

## Backend (API) localisation
- The user's language is stored in `user_preferences.language` (`en` | `el`), synced from the app's language switcher (PATCH `/users/me/preferences`) and sent on sign-up.
- `api/src/shared/i18n/messages.ts` is the server catalogue (same keys for `en` and `el`, enforced by a unit test); `I18nService` resolves a user's language and renders messages; `translate`/`msg` live in `translate.ts`.
- Localised server-side: notifications (title/body rendered per recipient), transactional emails (verify, reset, invitations — incl. footer), default quiz/deck/copy titles, notes-transform titles, summary "Sources" heading, attempt-analysis recommendations, readiness factors/blockers, study-plan advice, daily-session titles/reasons, dashboard greeting, level titles and achievements (`achievements.el.ts`).
- AI: every AI task (questions, flashcards, topics, summaries, recall prompts, tutor/Socratic replies, answer feedback, text actions, word lookups) is written in the **project's language** (`projects.language`, chosen in the project form, default = creator's UI language). Source material in another language is expressed in the project language; verbatim quotes keep the original wording. Calls without a project fall back to the user's interface language. Default titles created inside a project (decks, quizzes, notes, "Sources") also follow the project language.

## Content languages (project language)
Content languages are separate from UI languages: the registry in `api/src/shared/i18n/languages.ts` is the only thing needed to offer a new project language (code, English name, native name). DTO validation, AI prompts (`AiService.languageInstruction`) and the web selector (`GET /projects/languages` → `useProjectLanguages`) all read from it. To add e.g. French: add `{ code: 'fr', name: 'French', nativeName: 'Français' }`; no migration is required (`projects.language` is free text). UI translations (`messages.ts` + app locales) are optional and only affect interface strings — a language without them falls back to English for catalogue strings.
- API error messages stay English on the wire; the app translates them via the `serverErrors` namespace (`translateServerMessage` in `lib/api-error.ts`, keyed by a slug of the message, with regex patterns for messages containing values). When adding a new user-facing exception message, add it to `locales/{en,el}/serverErrors.json`.

## Greek style guide
- Polite plural (εσείς) for instructions and messages: «Δοκιμάστε ξανά», «Ανεβάστε έγγραφα».
- Buttons: nouns or short imperatives (Αποθήκευση, Διαγραφή, Έναρξη, Συνέχεια).
- Sentence case; no all-caps in strings (CSS handles uppercase eyebrows). Keep proper Greek accents (τόνοι); uppercase CSS drops them automatically in most fonts.
- Use «…» for quotes in Greek copy; ellipsis character `…`.
